## Phase 1 — Density overhaul (UI tightening, no schema changes)

The current UI was generated by AI following generic Tailwind defaults which produce generous spacing suited for desktop reading — not for a mobile-first, information-dense marketplace used by farmers on low-end Android devices with small screens. This phase makes the platform visually competitive with OLX, IndiaMART, and JioMart — platforms that Indian users are already comfortable with.

**The core principle: more information per scroll, not more breathing room.**

### 1a. Global spacing reductions

Apply these reductions globally across all pages:

- Section padding: reduce from `py-8 md:py-12` patterns → `py-3 md:py-5`
- Card internal padding: reduce from `p-4 md:p-6` → `p-3`
- Gap between cards in grids: reduce from `gap-4 md:gap-6` → `gap-2 md:gap-3`
- Page horizontal margins: on mobile, reduce side padding to `px-2` (not `px-4`) so the full screen width is used
- Section headings: reduce `mb-6` type margins below headings to `mb-2 md:mb-3`
- Hero section: cut vertical padding by 40% — the hero must not require scrolling to reach the category cards on a standard mobile screen
- Between-section gaps: reduce `my-8 md:my-16` type gaps to `my-3 md:my-5`
- Empty/spacer elements: remove any `<div>` elements that exist solely to add whitespace

### 1b. Category navigation strip

Current: 2-row grid of large category tab buttons, each with generous padding and large emoji icons.

Change to: **single horizontal scrollable strip** (no wrapping, scroll horizontally) with compact chips:
- Each chip: `px-3 py-1.5` padding, small icon (16px), short label, no line wrap
- Height of the entire strip: max 44px (one thumb-tap height)
- Active state: filled green background, white text
- Inactive: outline/border, dark text
- The strip must be scrollable on mobile — all 8 categories visible via horizontal scroll, not a 2-row grid
- The `?` help button moves to inside the category detail page header, not on the strip chip itself — remove it from the strip to save space

### 1c. Listing cards (browse view)

Current: large cards with generous internal padding, one column on mobile.

Change to:
- **2-column grid on mobile** for Equipment, Labor, Drone Didi, Bhoosa/Parali, Seeds/Fertilizers, Warehouse — these are browsable listings that benefit from more results visible at once
- **1-column (full width) on mobile** for Land only — land listings have more detail and benefit from full width
- Card height target: fit key info in ~100-120px per card (2-column) or ~80px per card (1-column land)
- Each card must show: category badge (small pill), listing type (Offer/Requirement), key detail (e.g. "Tractor — ₹800/acre"), location (village + distance), and time posted — all without tapping
- Remove any card shadows that add visual bulk without information value — use a simple `border border-gray-100` instead
- The "30-50 किमी दूर" separator between primary and fallback results: make it a compact divider line with small text, not a full-width banner

### 1d. Homepage sections

Current: large hero → large how-it-works → large resource cards → large category cards → live listings → mission → footer. Multiple sections require scrolling before any listings are visible.

Target layout (top to bottom, mobile):
1. **Compact hero** — max 180px height. Tagline (2 lines max) + 2 CTA buttons side by side. No decorative background elements that add height.
2. **Category strip** — the horizontal scrollable strip from 1b, immediately below the hero
3. **Live listings** — the most important section, immediately visible without scrolling on a typical mobile screen (720px+ height device). Show listing cards in 2-column grid.
4. **Mission strip** — a single horizontal bar (not a full section), 48px height, showing the two objectives as icons + short text: "🌾 किसान की आय बढ़ाना | 💼 रोज़गार के अवसर" — links to the About/Mission page
5. **Government contacts highlight** — compact 3-card row (horizontal scroll on mobile), not a full section with heading and subheading
6. **Articles** — compact 2-card row
7. **Footer** — reduce footer padding

### 1e. Help modals (? buttons)

Move the `?` help icon from the category strip chip to the listing creation form for each category — shown as a small info icon next to the form heading. This removes clutter from the primary browse UI while keeping the help available where it's most needed (when someone is actually filling in a form).

### 1f. Forms (listing creation)

- Field label + input: reduce gap between label and input from `mb-1` or `mb-2` to just `mb-0.5`
- Between form fields: reduce from `space-y-4` or `space-y-6` to `space-y-2`
- Form section headings: smaller, less prominent
- Submit button: keep full width but reduce padding from `py-3` to `py-2`

- All 8 category chips fit in a single horizontal-scroll strip (no wrapping to a second row)
- Listing cards in browse show key info without needing to tap

## Phase 3 — Vendor/Business tagging + admin reporting

### 3a. Schema change (migration 0017)

Add `listing_source` column to the `listings` table:

```sql
ALTER TABLE listings 
ADD COLUMN listing_source text NOT NULL DEFAULT 'farmer' 
CHECK (listing_source IN ('farmer', 'vendor'));
```

This single column distinguishes farmer-to-farmer listings from vendor/business listings across all categories. No separate account type — same signup for everyone. A vendor simply selects "Business/Vendor listing" when posting.

### 3b. Listing creation form change

At the very start of the listing creation flow (before category selection), add a single toggle/selector:

- Label (Hindi primary): "आप कौन हैं? / Who are you posting as?"
- Option 1: "👨‍🌾 किसान / Farmer" — default selected
- Option 2: "🏪 व्यापारी / दुकानदार / Business or Shop"

This selection sets `listing_source` on the listing. Once selected, the rest of the form proceeds exactly as now — no separate form, no separate flow.

When "Business/Shop" is selected:
- Show a small note: "आपकी लिस्टिंग पर 'व्यापारी' का बैज लगेगा / Your listing will show a 'Vendor' badge"
- Future listing charges may apply — show the same "भविष्य में लिस्टिंग शुल्क लागू हो सकता है" note already used in Agri-Inputs

### 3c. Browse view — Vendor badge

Vendor listings (listing_source = 'vendor') show a small "🏪 व्यापारी" pill/badge on the listing card and detail view — clearly distinguishing them from farmer listings. Farmers can then decide whether they prefer to deal with a shop or another farmer.

### 3d. Admin dashboard — Vendor reporting

Add a dedicated "Vendor Listings" report tab in the admin dashboard:

- Total vendor listings (by category)
- Total farmer listings (by category)
- A table showing all vendor listings: category, title/key detail, vendor's name, phone/email, pincode, created date, status
- Filter by category, by date range
- Export as CSV (basic — just generate a downloadable CSV from the table data)
- This becomes the foundation for future billing/monetization when listing charges are introduced

Also add to the existing platform overview stats: "Farmer listings: X | Vendor listings: Y" breakdown.

### 3e. Update dummy data

Update 3-4 of the existing dummy listings (specifically the vendor-type ones in Agri-Inputs — पटेल कृषि केंद्र, लोधी एग्रो सेंटर) to have `listing_source = 'vendor'` so the Vendor badge and admin reports are testable with existing data.

## Phase 4 — Warehouse category

**Category identifier:** `warehouse`
**Category name:**
- Hindi: `गोदाम / भंडारण`
- English: `Warehouse & Storage`

**Nav position:** Between Seeds/Fertilizers & More and Experts (6th position in the new order: Equipment → Labor → Drone Didi → Bhoosa/Parali → Seeds → **Warehouse** → Experts → Land)

**Who uses this:** Primarily vendors/businesses (warehouse owners), but a farmer with a storage space can also list. The listing_source toggle from Phase 3 applies here too.

**Homepage card:** Add as 6th card with a warehouse/storage icon and description:
- Hindi: "फसल सुरक्षित रखें — गोदाम किराए पर लें या दें"
- English: "Store your harvest safely — rent or offer warehouse space"

**Listing fields (Offer — warehouse owner):**
- warehouse_type (dropdown, required): सामान्य गोदाम/General Storage, शीत भंडार/Cold Storage, अनाज भंडार/Grain Silo, अन्य/Other
- capacity_quintals (number, required): storage capacity in quintals
- rate (text, required): "₹X प्रति क्विंटल प्रति माह / ₹X per quintal per month" or "₹X per day" etc.
- available_from (date, optional)
- facilities (multi-select, optional): बिजली/Electricity, पानी/Water, सुरक्षा/Security Guard, लोडिंग-अनलोडिंग/Loading-Unloading, वजन काँटा/Weighing Scale
- address (text, required): full address of the warehouse
- asset_pincode (required): for distance matching — where the warehouse is located
- contact_name (text, optional): person to contact (if different from account name)

**Listing fields (Requirement — farmer looking for storage):**
- crop_type (text, required): what they need to store
- quantity_quintals (number, required): how much they need to store
- duration (text, required): how long (e.g. "2 months", "until March")
- asset_pincode (required): where the crop is (farm location)
- preferred_type (dropdown): same as warehouse_type above

**Help modal content:**
- Hindi: "फसल कटाई के बाद तुरंत बेचने की मजबूरी से बचें — गोदाम में सुरक्षित रखें और अच्छे दाम का इंतज़ार करें। गोदाम मालिक अपनी जगह और दाम यहाँ लिस्ट कर सकते हैं।"
- English: "Avoid the pressure to sell immediately after harvest — store safely and wait for better prices. Warehouse owners can list their space and rates here."
