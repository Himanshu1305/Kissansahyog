11. **1D B17:** fixed at the source in `scripts/prerender.mjs` (+ `scripts/lib/prerender-html.mjs`): (a) the SPA fallback (and `/`) always serves the pristine Vite `index.html` kept in memory; (b) only `href`/`src` attributes of `<link>`/`<script>` tags that start with `http(s)://localhost|127.0.0.1[:port]/` are rewritten to root-relative; (c) a `<link rel=modulepreload|preload|stylesheet>` that exactly repeats an earlier one (same rel + href) is dropped. The runtime-injected modulepreload/stylesheet links are KEPT (root-relative, same-origin, they speed up the route's chunks). New read-only gate `scripts/check-no-localhost-dist.mjs [distDir]` is wired at the end of `build:full` AND at the end of `build:prod` (it only reads dist; safe for production and stops a leaking prod build before ship). Unit test `tests/unit/prerender-html.test.mjs`.
12. **1D B17, second leak found by the new gate: share links.** After the prerender fix, `check-no-localhost-dist` still failed on 22 pages (home, kisan-mela, yojana/*, articles, agro-forestry, drone-didi): WhatsApp share `href="https://wa.me/?text=…http%3A%2F%2Flocalhost%3A4178…"` built from `window.location.origin` while the snapshot ran on localhost. React does not patch attribute mismatches at hydration, so a visitor tapping share before a re-render would send a localhost link. Fix at the source, one line in `src/lib/native.js`: `publicOrigin()`/`publicHref()` use `PUBLIC_ORIGIN` (`https://kissansahyog.com`) when `window.__KS_PRERENDER` is set (the flag the prerender already sets for 10D). Alternative rejected: narrowing the gate to `<link>/<script>` only (would ship the leak). Side effect: on STAGING the prerendered share links say kissansahyog.com until the page re-renders (production: identical to the live origin). Main chunk unchanged in size.
