## How login state is stored

`authService.js` keeps the signed-in profile in `localStorage` (`SESSION_KEY`); email users additionally have a Supabase Auth session in `localStorage` under `ks_sb_auth`. Both live in the WebView's storage, which survives app restarts (proved by T15). `allowBackup=false` keeps it out of Android cloud backups.

## Permission decisions (Step 1)

| Permission | Decision | Why |
|---|---|---|
| INTERNET | declared | all data is live |
| ACCESS_COARSE_LOCATION, ACCESS_FINE_LOCATION | declared | "Share my location"; `getDevicePosition()` asks for `enableHighAccuracy` |
| RECORD_AUDIO | declared | voice-search fallback records audio (Android WebView has no SpeechRecognition) |
| **MODIFY_AUDIO_SETTINGS** | **declared — not in the brief's list** | Capacitor 8.5.3 `BridgeWebChromeClient.onPermissionRequest` requests `MODIFY_AUDIO_SETTINGS` **and** `RECORD_AUDIO` for any `AUDIO_CAPTURE` request and denies it unless both are granted. Without it the declared RECORD_AUDIO could never be used. Normal (install-time) permission, no prompt |
| **ACCESS_NETWORK_STATE** | **declared — not in the brief's list** | without it Android WebView cannot see connectivity, `navigator.onLine` stays `true` and the offline banner never shows; `@capacitor/network` requires it too. Normal permission, no prompt |
| `com.kissansahyog.app.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` | merged automatically | added by androidx.core to every app targeting API 33+; signature-level, app-private, not user-facing |
| CAMERA | **not declared** | the photo picker is `<input type="file" accept="image/*" multiple>` with **no `capture` attribute** (PhotoPicker.jsx:25); Capacitor only offers the camera when capture is set (`fileChooserParams.isCaptureEnabled()`), otherwise it opens the file/gallery picker, which needs no permission |

`uses-feature` location, location.gps and microphone are declared `required="false"` so devices without them can still install. T2 asserts this exact set (anything extra or missing fails).
