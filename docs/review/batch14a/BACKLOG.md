# Batch 14A backlog (things left on purpose)
1. **Block coverage.** The database refuses a blocked user on the two tables a signed-in user writes with their profile id: listings (posting) and kisan_mela_interest. Kisan Sawaal questions, complaints (reports), feedback, carbon suggestions and cold-storage claims are ANONYMOUS inserts with no user id, so a block cannot reach them (they stay rate-limited by IP/device as before). Contact reveal and WhatsApp opt-in are reads / profile updates, not inserts, and their functions were left untouched on purpose. A blocked person cannot log in by phone (server check) and every session of theirs is revoked at block time. E-mail-login users get a new session from the old function, but cannot post.
2. **Admin action log coverage.** Recorded by the console (adminApi.js withLog), not by a database trigger: listing remove/sponsor, report resolve, article save/delete, expert save/active, yojana save/active, MSP save, resource save, Sawaal answer, Safalta save, site setting, procurement save, mela save, plus (in the database) announcements, security switches, block/unblock and role changes. NOT logged: the "set active/featured/published" toggles for MSP, resources, Safalta, Sawaal (featured/published), input prices, subscriptions, melas (status/active/delete/split), candidates, carbon suggestion resolve, page FAQs, procurement delete, Safalta/Sawaal delete, CS claims; listing disable/enable/delete already have their own 10G audit table. Anything done directly in SQL or by Claude is also not in this log.
3. **Rate-limited OTP refusals** are not stored by 0066, so the SMS usage panel shows "not tracked" for them. 7- and 30-day counts start from when 0067 is applied (plus the last 2 days of rows that still exist).
4. **Last-super-admin guard** cannot trigger through the console (the actor must be a different super admin), it is kept as a second line of defence.
5. Old admin RPCs still accept any admin (editor or super) and do not need a session when session_enforced is false; only the new tools are strict. Turning session_enforced ON (after 14A) makes the old ones strict too.
6. The old full "Users contact list" panel (phone and e-mail visible to every admin) is kept unchanged in People. Decide later whether editors should see it.
7. 14B (AI article drafts) will reuse functions/lib/admin-auth.js.
