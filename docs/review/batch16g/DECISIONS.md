# Batch 16G decisions

1. Base: tag `ship-16f` (production). `main` lacks 16F; this branch is merged into `main` later (SHIP.md step 4).
2. Thresholds (constants at the top of `src/lib/weather/freshness.js`): fresh <= 4 h, aging <= 12 h, stale <= 24 h, expired > 24 h. "Now" values are re-estimated from the nearest forecast hour when the cell is older than 90 min (`current_estimated`, shown as "approx.").
3. Expired (> 24 h): /mausam hides the "now" card, farm-action windows, 48-hour strip, 7-day table, 16-day table and the WhatsApp share button; it shows the age line, the notice with the IMD link and the existing "weather unavailable" text. Season rainfall, glossary, FAQ and sign-up stay. (Default decision from the prompt.) The homepage tile shows "weather unavailable" and drops the rain line; the advice tile then behaves as when there is no weather.
4. Trimming happens once, in `normalize()` of `weatherApiV2.js`, so /mausam, the homepage tile, the rain alert and the farm rules all see the corrected data. `fresh` and `age_ms` are added to the normalized cell.
5. A phone in another time zone: hourly text, day names and dates in `Mausam.jsx` are read as IST (checked by screenshots taken with the browser set to America/Los_Angeles).
6. The "Updated ..." line uses 12-hour time in English and Hindi period words (सुबह/दोपहर/शाम/रात); older than yesterday shows dd/mm. Digits stay Latin, like the rest of the site.
7. Known, left alone (rule: nothing else changes in `weatherApiV2.js`): the browser-side `fetchLiveWeatherCell` pre-cuts its hourly list with the phone's zone; on a non-IST phone it can drop some early hours. `trimToNow` still corrects what is kept. The cron path (the normal one) is not affected.
8. GitHub job caps, as read from the files: the workflow has `timeout-minutes: 20` per job (matrix: production and staging); every Open-Meteo request has its own limit (forecast 20 s, archive 30 s); the database calls have none. Before this batch a stalled step ran until GitHub cancelled the job at 20 min (a grey "cancelled", not a red failure). Now: the weather step is cut off at 12 min (`weatherTimeoutMs`), the checks still run and the job ends RED; a hard stop at 17 min is the last resort. `runWatchdogJob` got two optional parameters (`weatherCheck`, `weatherTimeoutMs`); without them it behaves exactly as before, and the price freshness watchdog is unchanged.
9. RED rules (production and staging): a pilot cell that fails (after all other cells were tried), or the Sagar cell `23.8_78.7` missing / fetched more than 2 h before the check. The check is one read-only select on `weather_cache_v2`. `--dry-run` still opens no database connection.
10. After a stall the process exits explicitly (`process.exit`), because a hung request could keep it alive.
11. Ship scripts were edited by hand from the 16F ones. The database probe, the 15B page checks and the 16B admin-page checks were removed (this ship is site-only and these belong to earlier batches). References to `ship-16f` that remain are the intended ones (first gate, expected live deployment).
12. No new tests of the e2e type: the existing home / mausam checks were run; the prerender-based ones (H4, collapsible C1) need `build:full` and fail on a plain build, as before this batch.
13. No separate i18n audit script exists; the unit suite checks hi/en for every new key.
